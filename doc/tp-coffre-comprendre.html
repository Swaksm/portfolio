1 · Le TP en bref

  • « Clé d’équipe » : gestionnaire de mots de passe en SaaS, plusieurs entreprises
  • Groupe de 2, 3 h, conception seulement (pas de code), données fictives
  • Comité : qui lit un secret ? comment retirer l’accès ? comment vérifier le retrait ?

Source : cours, chapitre 16

2 · Qui est qui

  • Tenant : espace isolé d’une entreprise cliente
  • Entrée : titre + identifiant + secret ; privée ou partagée à des personnes nommées du même tenant
  • Partage : limité dans le temps, retirable avant l’échéance

Hors périmètre : liens publics, partage entre entreprises, hors ligne. À choisir par vous : connexion au coffre, récupération d’accès.

Source : cours, chapitre 16

4 · C4 : dessiner par niveaux de zoom

  • C1 Contexte : utilisateurs, systèmes externes, périmètre
  • C2 Conteneurs : applications et stockages (≠ forcément Docker)
  • C3 Composants : intérieur d’un conteneur
  • C4 Code : pas toujours utile
  • C1 + C2 suffisent souvent pour commencer ; le TP demande ces deux-là

Source : cours, chapitre 4

Source : cours, chapitre 16

5 · DFD : suivre les données

  • Entités externes, processus, stockages, flux
  • Frontière de confiance : là où la confiance change (pas forcément un réseau ; 2 tenants dans une base = frontière)
  • Par flux : qui parle à qui, quelle identité, quelles données, quels droits, que se passe-t-il si échec, comment détecter un abus

Source : cours, chapitre 5

TP : DFD sur octroi, lecture, retrait ; montrer frontières, point de déchiffrement, clés, traces, sauvegardes.

Source : cours, chapitre 16

6 · STRIDE : chercher les menaces

LettreMenaceQuestion
Susurpationse faire passer pour quelqu’un ?
Taltérationmodifier sans droit ?
Rrépudiationnier une action faute de traces ?
Idivulgationlire du confidentiel ?

  • Exemple cours : entreprise A lit une facture de B = BOLA ; la solution n’est pas le MFA mais vérifier le droit sur cet objet
  • STRIDE ne note pas les risques et n’est pas exhaustif

Source : cours, chapitre 6

7 · Noter les risques

  • Impact (1 à 4) × vraisemblance (1 à 4) = indicateur de priorité, pas une mesure scientifique
  • Un contrôle dessiné ne rend pas le risque faible : tests, implémentation, exploitation

Source : cours, chapitre 7

8 · Protéger

  • Moindre privilège, défense en profondeur, Zero Trust
  • Droit absent ou incertain = refus
  • Pas de secrets ni de jetons dans les journaux

Source : cours, chapitre 8

  • Authentification = qui ; autorisation = quel droit ; traçabilité = qui a fait quoi
  • Le tenant ne doit pas venir seulement du navigateur

Source : cours, chapitre 9

  • Chiffrement en transit / au repos : n’empêche pas une application autorisée mais compromise de lire
  • Sauvegardes protégées, restauration testée

Source : cours, chapitre 10

Référence citée par l’énoncé : OWASP Authorization (refus par défaut).

  • Statut, contexte, options, décision, justification, conséquences, validation, risque résiduel
